# README alt text
Franz Badenhorst, revenue infrastructure engineer, Pretoria. I fix what happens after the lead comes in. Most businesses don't have a marketing problem. They have an operational delay problem. Below, his revenue system drawn as one isometric plant, six systems in one loop: 01 lead lands, a Meta Lead Ads webhook; 02 straight to dial, a lead to dialler bridge into ViciDial; 03 on the call, speech-to-form fills the record while the agent talks; 04 closed, client apps on Supabase; 05 counted, read-only web reports synced every minute; 06 back to the ad, where live spend picks the creative. Leads flow through the pipes; a return pipe carries the spend signal back to the ad.
02, on the floor. The same loop, played out on a floor plan, an illustration and not live data: leads from ad creatives A, B and C pass the webhook (1) and the dialler (2) and go to the next free desk; desks light when a call connects and speech-to-form fills the record (3); sales go to client apps on Supabase for applications, referrals and appointments (4); the reports board recounts every minute (5); and live spend picks the creative (6).
Full stack, literally: an isometric city of 93 repositories, 43 of them private. Each tower is a technology and its height is how many repos depend on it. interface: React 58, Tailwind CSS 55, Vite 48, React Hook Form 35, React Router 35, Recharts 35, shadcn/Radix 35, TanStack Query 35, Next.js 12, Framer Motion 11, Electron 1; services: Zod 39, Node.js HTTP 13, SendGrid/Resend 6, FFmpeg 2, Flask 1; data: Supabase 13, PL/pgSQL 7, Drizzle/Prisma 2, PostgreSQL 2, SQLite 1; infra and delivery: ESLint 39, GitHub Actions 18, Vercel 12, Vitest/Jest 4, Playwright 3, Docker 1; ai: Gemini API 7, MCP 1, OpenAI API 1. The city stands on 18.6 MB of code, layered by language.
